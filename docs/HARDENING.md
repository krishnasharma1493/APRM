## Notes (observations, not failures; nothing was changed for them)

- **N1. Internal helpers trust their pointers.** `metrics_ratio9` (`core/metrics.c:90`) writes `*whole` and `*frac` without a NULL check, and the `json_*` writers, `csv_text_*` and `eventlog_*` functions assume a non-NULL buffer. None is reachable from outside: the only callers are other `core/` functions that pass locals, and every external path goes through the checked `sim_*` and `aprm_*` entry points (6.1). Left alone (not an API entry point of PRD §5).
- **N2. Hostile CSV memory on the website (fixed).** A 1 MB file of empty lines used to make `parseCsv` keep about one million error objects. It now stores at most 1000 (`MAX_ERRORS_STORED`) while `errorCount` still counts every bad row; the status line and the "... and N more bad rows not shown" line use the count, and the screen still lists 200. Test: `tests/web/test_editor.mjs` "hostile 1 MB files" (1 MB of newlines and of `x` lines: counts exact, 1000 stored, under 3 s).
- **N3. `<out>.tmp` in the console program (fixed).** `write_temp` used `fopen(..., "wb")`, which would write through a pre-existing file or symlink named `<out>.tmp`. It now removes a stale `<out>.tmp` first and creates it with `open(O_WRONLY | O_CREAT | O_EXCL)`; the write-then-rename order is unchanged. Test: `tests/cli/run_cli_tests.sh` "stale <out>.tmp symlink is not written through" (fails on the old code, passes now).
- **N4. A module that never settles (fixed).** `init()` in `web/js/wasm.js` now races the engine factory against a 30 s timeout (`START_TIMEOUT_MS`) and rejects with an `EngineError` ("The engine took too long to start. Reload the page or use the backup video."); a late answer after the timeout is ignored. The existing error state (`web/js/app.js`) shows it. Tests: `tests/web/test_web.mjs` "a factory that never settles times out after 30 s" (fake timers, late resolve ignored).
- **N5. Mutable globals in `wasm/api.c`** (`g_slots`, `g_cap`, `g_orphan_err`, `g_orphan_buf`, lines 80-83): outside `core/`, documented, single-threaded, needed for the handle table. `g_slots` and the orphan buffer are never freed (they live as long as the module); `leaks` does not count them because they stay reachable.
- **N6. `sim_log_json` on failure** can leave partial text in `*out` (the other three `sim_*_json` functions reset it, `core/engine_json.c:84,105,212`). The only caller, `wasm/api.c:386-390`, re-renders the buffer as an error envelope, so nothing leaks to the page.
- **N7. Dead branch.** `core/engine.c:470` `if (rc != APRM_OK) return rc;` after `policy_wait_key` can only fire for input that `sim_add_job` already refused; it is commented as such and kept as a tripwire. Returning there would leave a step half done, so it must stay unreachable (it is: 88200 fuzz runs and 15000 stress runs never reached it).
- **N8. Memory of the event log in the console program.** The log is always built, even without `--log`; for the 1,000,000-job maximum it holds several million 56-byte entries. Not measured, no limit exceeded in the tests.
- **N9. CI.** `make hardening` is now a step of the `sanitize` job in `.github/workflows/ci.yml` (the only change to that file). It has not yet run on Linux/GCC at the time of writing; if it fails there, the failure is in the harness portability (flags, `nm`), not in `core/`.
